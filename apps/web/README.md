# `apps/web` frontend

This package contains the React 19 + TypeScript + Vite 8 Progressive Web App for the Gemini Web Wrapper workspace.

## What the frontend does

The app provides these primary views:

- **Chat** — main OpenAI-compatible chat interface
- **Agent** — SSE-driven agent chat UI backed by `/v1/agent/chat`
- **Shell** — WebSocket sessions, multi-pane layouts, Ghostty rendering, and `webassembly.sh` fallback
- **Editor** — code editing and review
- **Files** — GitHub file browsing plus repo index status and search
- **Settings** — gateway key, GitHub token, repo, provider, and model configuration

## Tooling

Exact versions are pinned in `package.json` (`packageManager`, dependencies) and the root `mise.toml`; this README does not duplicate them.

- Bun, Node.js 24
- React 19, Vite 8, TypeScript, Vitest
- Biome and oxlint for linting

## Commands

```bash
cd apps/web
bun install
bun run dev
bun run test
bun run lint
bun run typecheck
bun run build
```

Local dev server: `http://localhost:5173`

The Vite dev server proxies `/v1/*` and `/api/*` to `http://localhost:9000` by default.

## Configuration

The Settings screen manages:

- the backend gateway API key,
- the GitHub token used for private repo browsing and repo indexing,
- the active repository and branch,
- the selected provider and model, and
- optional custom OpenAI-compatible providers.

Built-in providers are defined in `src/services/providers.ts`:

- Gemini
- Anthropic
- GitHub Copilot
- OpenCode Zen
- Kilo Gateway

Users can also add custom providers by supplying a provider ID, model list, and base URL.

## Storage behavior

Configuration persistence is split intentionally:

- `sessionStorage` keeps the full config for the active browser session
- `localStorage` stores only the sanitized non-sensitive configuration when “remember” is enabled

## PWA

The service worker and manifest are generated by `vite-plugin-pwa` (see `vite.config.ts`). Do not add a hand-written manifest to `public/`; the generated `manifest.webmanifest` is the one served.

- Install icons are PNGs in `public/` (`icon-192.png`, `icon-512.png`, `maskable-icon-512x512.png`, `apple-touch-icon.png`). The source artwork is in `public/icons/*.svg`; regenerate PNGs from it (for example with ImageMagick `magick -density 384 -background none <svg> -resize <n>x<n> <png>`) when the artwork changes. The maskable icon must stay full-bleed (no rounded corners).
- App shell and assets are precached. API paths (`/v1/*`, `/api/*`, `/health`) are excluded from the navigation fallback.
- Third-party resources (Google Fonts, Wasmer SDK/registry, webassembly.sh) use runtime caching with explicit expiry.
- Updates apply automatically (`registerType: 'autoUpdate'`); host `sw.js` and `index.html` with `no-cache`.
- To check installability, run `bun run build && bun run preview` and use the Lighthouse or Application tab in Chrome DevTools.

## Build output

A production build writes static assets to:

```text
apps/web/dist
```

That directory is what the release workflow packages and what static hosts such as Netlify or Vercel should publish.
